# ONCOURT 시네마틱 스크롤 — 검토용 수정본

작업일: 2026-11-01. 운영 배포·GitHub/Vercel 연결 변경 없음.

## 적용 내용과 현재 상태

첨부 ZIP의 HTML/CSS/JavaScript를 직접 수정했습니다. GNB와 Hero→Problem 전환이 수정 범위입니다. Connection부터 footer까지의 HTML은 첨부본과 동일하며 기존 style.css, 이미지와 이후 섹션 기능은 유지했습니다. 공통 컨테이너도 첨부본의 1360px을 유지합니다.

GNB 배경은 투명합니다. Hero/암막/영상에서는 흰색, 밝아지는 Problem부터 검은색 로고·메뉴로 전환합니다. 아래로 스크롤하면 숨고 위로 스크롤하면 다시 나타납니다. 메뉴 열기 버튼을 제거하고 홈 / 대회 / 블로그 / 앱 다운로드를 표시합니다. 홈은 Hero 시작, 대회는 기존 Beyond 섹션, 앱 다운로드는 기존 CTA로 연결합니다. 실제 블로그 URL이 없어 블로그는 비활성 상태입니다.

첨부 프로젝트의 Hero는 이미지였고 별도의 Hero 반복 영상이 없었습니다. 이 이미지를 보존했으며 현재 요청에 따라 FIND YOUR RALLY.와 3개 가이드라인을 추가했습니다. 따라서 **Hero 자동 반복 영상은 구현하지 않았습니다.** 제공된 포핸드 영상을 Hero 루프로 중복 사용하지 않았습니다.

## 구조

- index.html: 원래 Hero/Problem을 하나의 cinematic-stage에 배치. 별도의 커튼 6개, 영상/정지 프레임, 공 기준 이미지, WebGL 레이어를 추가.
- css/cinematic.css: 전환에만 적용되는 마지막 스타일시트. 커튼마다 2px 중첩으로 틈 방지. 영상은 contain으로 원본 좌표 보존. 고정된 그라데이션 마스크와 비네팅으로 주변부를 어두운 무대와 연결.
- js/cinematic.js: GSAP 3.13 ScrollTrigger 하나로 stage를 pin. end는 뷰포트 높이의 7배. 정규화된 progress를 모든 장면이 함께 사용. 반대 방향에서도 같은 함수로 상태를 재계산. 화면 크기 변경 후 핀을 해제하고 다시 측정하며, 구멍 좌표는 실제 DOM getBoundingClientRect()로 매번 계산.
- Three.js 0.170: 실제 SphereGeometry(64×48), MeshStandardMaterial, 소스 공의 앞면을 투영한 UV 텍스처, 미세한 bump, 직교 카메라. 픽셀 비율 최대 1.5. 스크롤/리사이즈 시만 렌더링하며 pagehide 시 자원 해제.
- 원본 공을 잘라낸 이미지→3D 메시를 같은 좌표·직경에서 교차 전환. WebGL 불가 환경에서는 추출 이미지로 낙하를 이어가는 대체 동작.
- 공은 이차 가속 곡선으로 낙하하고 구멍 너비의 80% 이내로 수렴. 진입 중 축소와 구멍 앞쪽 가장자리 기준 clip-path로 가림. 구멍 자체의 디자인/콘텐츠 안 위치는 보존. 입장 장면에서는 Problem 그룹 전체를 아래에 두었다가 공이 사라진 후 원래 중앙 위치로 복귀.
- prefers-reduced-motion: pin/영화/낙하를 건너뛰고 기존 Hero와 Problem을 정상 문서 흐름으로 표시하도록 구현.

## 장면 설정

js/cinematic.js의 CONFIG 값이 조정점입니다. 값은 전체 스크롤 길이에 대한 비율입니다.

| 구간 | 값 | 동작 |
|---|---:|---|
| 커튼 닫힘 완료 | .16 | 패널 순차 scaleX, 모두 닫힌 뒤 Hero 숨김 |
| 영상 등장 | .17–.20 | 어두운 무대에 영상 등장 |
| 영상 스크럽 | .20–.65 | 0–7.500초, 24fps 단위 탐색 |
| 배경 암전 | .68–.74 | 영상은 어두워지고 원본 공 이미지는 유지 |
| 3D 전환 | .74–.80 | 원본 공과 메시 교차 전환 |
| 낙하 | .80–.94 | 가속 낙하·회전·원근 축소 |
| 밝은 배경 | .83–.94 | 암막에서 흰색으로 전환 |
| 구멍 진입 | .94–.975 | 실제 구멍 좌표로 진입·축소·가림 |
| Problem 정착 | .975–1 | 콘텐츠 중앙 복귀 및 문구 등장 |

추가 조정점: scrollScreens=7, stopTime=7.5, 패널별 시차 .014, 텍스트 등장 .978, GNB 색 전환 .88, Problem 임시 이동 45vh, 착지 직경 상한 구멍 너비×.8, 영상 마스크·비네팅은 CSS, 공 질감/조명은 setupMesh(). 정지 시점을 변경하면 기준 프레임·cutout·텍스처·좌표도 함께 갱신해야 합니다.

## 영상과 프레임 분석

실제 첨부 파일명은 ONCOURT_ball_continuous_v5(1).mp4였습니다. 원본은 media/forehand-original.mp4에 바이트 그대로 보존했고 cmp 일치를 확인했습니다.

- 원본: 1920×1080, 24fps, 217프레임, 약 9.0417초.
- 7.0초부터 약 7.96초까지 24개 후보를 추출해 비교했습니다. docs/stop-candidates.jpg 참조.
- 선택: **00:00:07.500, 0부터 세는 인덱스 180 / 1부터 세는 181번째 프레임.**
- 원본 좌표 기준 공 중심 약 (936,459), 추출 영역 (827,350), 218×218px. 구형 경계는 시각 측정치입니다.
- 색은 노랑·연두 혼합, 밝은 곡선 심이 앞면에 보이며 윗부분이 밝고 아래가 어둡습니다. 후반 프레임보다 크기가 작고 앞면 형태가 식별됩니다. 소스 자체의 부드러운 블러는 남아 있습니다.
- assets/cinematic/stop-frame-180.png: 전체 기준 프레임.
- ball-cutout.png: 원본 공의 타원 알파 마스크 추출.
- ball-uv.png: 촬영된 앞면 투영. 보이지 않는 뒷면과 심은 추정입니다.
- felt-bump.png: 절제된 섬유 표면용 노이즈.
- stop-metadata.json: 시간/프레임/좌표.
- media/forehand-scrub.mp4: 7.541667초까지의 별도 all-intra H.264, 무음. 탐색 간격을 줄였으며 원본은 수정하지 않았습니다.

최적화 영상 생성 설정:

```sh
ffmpeg -i media/forehand-original.mp4 -t 7.541667 -an -c:v libx264 -threads 2 -preset ultrafast -crf 20 -g 1 -pix_fmt yuv420p -movflags +faststart media/forehand-scrub.mp4
```

## 완료로 단정하지 않는 항목

1. 검수 브라우저가 WebGL 컨텍스트를 만들지 못해 실제 Three.js 렌더링과 영상→3D의 시각 정합은 검증하지 못했습니다. 소스에는 실제 구형 메시가 구현되어 있으나 브라우저 검수는 `reference-image-fallback` 상태에서 이루어졌습니다. 따라서 3D 전환이 눈에 띄지 않는다거나 사실적인 섬유/조명 완성도를 달성했다고 주장하지 않습니다. WebGL 지원 브라우저에서 dataset.renderer가 `three-webgl`인지 확인하고 별도 시각 검수가 필요합니다.
2. 선수·라켓을 시간별로 정밀 로토스코핑하지 않았습니다. 윤곽 보존을 위해 요청에 허용된 비네팅/그라데이션 대안을 적용했습니다. 펜스·나무 등 소스 배경은 일부 남습니다.
3. 낙하 대체 이미지는 2D이며 실제 회전은 WebGL 메시에서만 구현됩니다. 뒷면 질감과 심은 추정이고 고급 퍼/동적 모션블러·물리 엔진은 적용하지 않았습니다. 소스 공의 저해상도/블러 때문에 확대 시 질감 재현에 한계가 있습니다.
4. Hero 반복 영상 자산은 제공되지 않았으므로 기존 정지 이미지를 유지했습니다. 블로그 실제 URL도 추후 필요합니다.
5. 모든 완료 기준을 충족했다고 판단할 단계는 아닙니다. 특히 실제 GPU에서의 3D 검수와 Safari/모바일 영상 탐색 성능 검수가 남습니다.

## 실행 및 확인

파일 더블클릭(file://) 대신 HTTP 서버로 실행해야 ES module과 영상이 정상 로드됩니다.

```sh
cd renewal-web
python3 -m http.server 8080
```

http://localhost:8080/index.html 에서 스크롤합니다. qa.html은 뷰포트/단계 이동을 위한 개발 검수 페이지이며 실제 랜딩페이지 UI에는 노출되지 않습니다. 크기 변경 안정화 후 단계 이동이 실행되도록 짧은 지연을 둡니다.

기존 README와 docs에는 이전 수정 이력이 포함되어 있습니다. 이번 수정의 최신 설명은 이 문서입니다. 운영 자동 배포는 하지 않았고, ZIP에는 기존 호스팅 설정 원문을 보존했습니다.
