# ONCOURT — Scroll-Driven Tennis Ball Journey 구현 결과

이번 문서가 최신 기준입니다. 기존 정적 Match 보고서의 설명은 이번 구현으로 대체합니다.

## 수정 파일
- index.html: #match만 새로운 Sticky Stage 구조로 교체.
- css/style.css: #match 전용 스타일과 명시적으로 요청한 Hero/Connection 간격 규칙 추가.
- js/script.js: 기존 코드를 유지하고 중복 초기화를 막는 Match 모듈 추가.
- Hero 제목은 좌측 하단 48px 여백에 배치. Connection 소개와 CONNECT 간격은 기존 섹션 간격 토큰의 1.65배로 확대.
- #match 밖 HTML은 업로드한 ZIP과 완전히 일치하며, GNB/Footer/이미지 경로/다운로드 URL/컬러 토큰을 변경하지 않았습니다.

## 1. GSAP / ScrollTrigger 대신 적용한 구조
외부 CDN·패키지 없이 작동하도록 CSS position:sticky와 requestAnimationFrame 기반의 네이티브 스크롤 모듈을 사용합니다. GSAP이나 ScrollTrigger는 설치하지 않았습니다. 실제 스크롤 위치 하나에서 모든 상태를 계산하므로 지연 scrub 상태나 별도의 애니메이션 시간이 없습니다.

Stage 높이는 100svh에서 실제 헤더 높이를 뺀 값입니다. 섹션은 Stage의 5배 높이이며 실제 진행 범위는 4배입니다. 높이 932px의 검수 화면에서 852px Stage, 4260px 섹션(약 457vh)입니다. 창/visualViewport 크기 변경, load, 폰트 준비 시 좌표를 다시 계산합니다.

## 2. 이동 경로
화면에 표시한 단일 SVG path에 getTotalLength/getPointAtLength를 적용합니다. 경로와 공이 같은 부모 좌표계에 있고, 해당 좌표계만 스크롤에 맞춰 이동합니다. 공 중심은 경로 좌표와 동일합니다. 공의 회전량은 경로를 따라 이동한 거리에서 산출하고 그림자는 공과 함께 이동합니다. 점프·바운스·별도 트레일은 없습니다.

## 3. 활성 타이밍
| 구간 | 내용 |
|---|---|
| 0–13% | Step 01 정지 및 읽기 / 왼쪽 |
| 13–24% | 두 번째 체크포인트로 이동 |
| 24–39% | Step 02 등장 및 읽기 / 왼쪽 |
| 39–51% | 세 번째 체크포인트로 이동 |
| 51–65% | Step 03 등장 및 읽기 / 오른쪽 |
| 65–77% | 네 번째 체크포인트로 이동 |
| 77–88% | Step 04 등장 및 읽기 / 오른쪽, CTA |
| 88–100% | Step 04가 95%까지 흐려지고 공은 아래로 퇴장 |

공 도착 후 첫 3%에서 텍스트가 나타납니다. 텍스트 이동 대신 opacity만 사용합니다. 서로 다른 두 단계의 표시 구간은 겹치지 않습니다. 이동 중 잠깐 텍스트가 없는 구간은 경로 이동을 보여주기 위한 의도입니다.

## 4. Step 04 이후 퇴장
진행도 88% 이후에는 배경 경로의 세로 위치를 고정하고 공만 동일 경로의 남은 구간을 따라 내려갑니다. 끝점은 Stage 하단보다 공 크기만큼 더 아래입니다. 공의 opacity/scale은 변경하지 않습니다. 진행도 100%에서 공 전체가 clipping 영역 밖에 있고, 그 다음 스크롤부터 CSS sticky가 자연스럽게 해제됩니다. 별도 빈 Spacer나 pin 해제 점프가 없습니다.

## 5. 브라우저 검수
- 1440px: Step 01→02→03→04, 퇴장, 역스크롤 Step 03 복귀 확인.
- 같은 진행도 57%에서 복귀 전후 거리 3027.481px, 공 중심 Y 468.60px로 일치.
- 관찰한 경로 좌표와 공 중심의 화면 오차 0.006px 미만.
- 끝점에서 공 상단 965px, Stage 하단 932px: 공 전체가 화면 아래로 퇴장. 이후 Stage 하단이 위로 이동하고 05 섹션이 따라 진입.
- 320/390/430/768/1024/1440/1740px: 가로 넘침 없음. 표시 단계 한 개, 공·본문 영역 겹침 없음.
- 390px 문단 내부와 CTA의 실제 텍스트 잘림 없음. 모바일 가독성 마스크의 여백 때문에 장면 컨테이너 scrollWidth는 12px 더 크게 측정될 수 있으나 문구/페이지 넘침은 없습니다.
- reduced-motion 분기: 검수용 환경에서 설정값을 모의 적용해 네 단계가 모두 불투명한 일반 문서 흐름으로 복원되고 Sticky가 꺼지는 것을 확인했습니다. 실제 OS 설정 전환은 별도 확인이 필요합니다.
- node --check 통과, 고유 ID 및 내부 링크·이미지 경로 확인.

## 6. 제한 및 추가 확인
검수는 클라우드 Chrome에서 진행했습니다. 실제 iOS Safari와 Android의 주소창 축소·확대 및 터치 관성 스크롤 체감은 기기 검수가 필요합니다. Iceberg는 조회 시간 초과, ESPN은 검증 페이지로 인해 현재 라이브 디자인 대조를 완료하지 못했습니다. 첨부 이미지와 요청한 색상/정렬/순서를 우선 적용했습니다. 알려진 기능 오류는 발견하지 못했습니다.
